## Overview

Preference data is the foundational signal for [[concepts/rlhf]] (Reinforcement Learning from Human Feedback). Rather than attempting to specify human values as explicit loss functions — which is effectively impossible — preference data captures relative judgments between model outputs. A human (or AI) evaluator sees two completions for the same prompt and indicates which is better.

The key insight: it is far easier to compare two outputs than to generate a good one from scratch. The chosen response is not necessarily globally optimal — it is "better relative to the alternatives shown."

## Collection Methods

### Interface Designs

- **Pairwise comparison**: the dominant approach — annotators choose between two completions
- **Likert-scale granularity**: A>>B, A>B, Tie, B>A, B>>A — captures preference strength
- **Unary feedback**: thumbs up/down from production systems (lower quality but cheap at scale)
- **Arena-style**: head-to-head model comparison with tie option (e.g., Chatbot Arena)

### Rankings vs Ratings

**Rankings** (relative ordering) are the dominant paradigm. **Ratings** (absolute 1-5 scores) can be converted to pairwise preferences but add noise through different annotators' calibration baselines.

## Data Format

Standard structure: prompt + chosen completion + rejected completion + optional metadata (ratings, explanations, multi-turn context). For multi-turn conversations, preferences are typically collected on the final response, with prior turns masked from the training loss.

## On-Policy vs Off-Policy

The most critical quality dimension. **On-policy data** is generated by the model currently being trained (or a closely related model). It significantly outperforms **off-policy data** from unrelated models or aggregated public datasets.

The reason: different models have distinctive generation patterns. Preference data from a closely related model provides more robust signal in the areas where optimization actually matters. This creates operational complexity — live inference endpoints must be available during data collection.

## Major Public Datasets

- **[[entities/anthropic-hh-rlhf]]**: 170K comparisons (helpful + harmless + red teaming) — the foundational open dataset
- **HelpSteer2** (NVIDIA Nemotron team): largest recent human preference dataset
- **UltraFeedback**: ratings-to-pairs conversion methodology
- **Chatbot Arena**: implicit preferences from user voting

However, "there are no open models with fully open human preference data released with the methods used to collect it" — a significant transparency gap.

## Quality and Bias Challenges

Common biases that readily transfer to trained models:
- **Prefix bias**: beginning of response disproportionately influences judgment
- **Sycophancy**: over-agreement with user beliefs reduces truthfulness
- **Verbosity bias**: longer responses preferred despite equal quality
- **Formatting bias**: specific structures (lists, bullet points, emojis) drive preferences regardless of content quality

## Operational Reality

Preference data collection is expensive and wasteful:
- Vendor selection is supply-constrained; budget and brand influence priority
- Phased delivery: weeks 1-3 for calibration (higher rejection rates), weeks 4+ for model improvement
- "Millions of dollars spent on these datasets are wasted and not used in final models"
- Non-integrated data becomes stale quickly

## Data Format Variants Across Methods

Different alignment methods require different preference data formats:

| Method | Format | Min Scale |
|--------|--------|-----------|
| [[concepts/rlhf]] / [[concepts/dpo]] | Prompt + chosen/rejected pair | ~10-50K |
| [[concepts/kto]] | Prompt + response + binary label | ~12K |
| ORPO | Prompt + chosen/rejected | ~7K |
| SPIN | Prompt + chosen (auto-generates rejected) | ~1.8K |
| [[concepts/rlaif]] | AI-generated pairwise labels | ~125K |

Well-curated data allows dramatic size reduction: SPIN achieved comparable results with 1.8K vs 50K prompts, and ORPO succeeded with just 7K instances ([[sources/argilla-rlhf-alternatives-overview]]).

## AI-Generated Preference Data

[[concepts/rlaif]] automates preference annotation using LLMs, achieving statistical parity with human labels. Key findings:
- Soft labels (log probability distributions) outperform hard binary labels
- Chain-of-thought prompting improves AI label quality
- Larger models produce better annotations
- Generic pre-trained LMs suffice without task-specific fine-tuning
- Using AI feedback for preference datasets is now widely accepted practice
