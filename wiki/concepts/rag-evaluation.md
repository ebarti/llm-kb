## Overview

RAG Evaluation is the discipline of measuring the quality, reliability, and performance of [[concepts/retrieval-augmented-generation]] systems. As RAG has moved from research prototypes to production enterprise systems, evaluation has become critical — and significantly more complex than evaluating either retrieval or generation in isolation.

The core challenge is that RAG systems have **two failure modes that interact**: the retriever can fetch wrong documents, and the generator can misuse correct documents. Effective evaluation must diagnose which component is responsible for errors.

## Three-Tier Evaluation Framework

### Tier 1: Retrieval Quality

These metrics assess whether the system finds the right documents:

| Metric | What It Measures | Formula Intuition |
|---|---|---|
| **Precision@k** | Fraction of top-k documents that are relevant | Relevant in top-k / k |
| **Recall@k** | Fraction of all relevant documents that appear in top-k | Relevant found / Total relevant |
| **MRR** (Mean Reciprocal Rank) | How high the first relevant document ranks | 1 / rank of first relevant |
| **nDCG** (Normalized Discounted Cumulative Gain) | Graded relevance weighted by position | Rewards relevant docs ranked higher |

### Tier 2: Generation Quality

These metrics assess whether the system produces faithful, useful answers:

- **Faithfulness**: Does the output stay grounded in retrieved context? (The most critical metric — unfaithful generation is hallucination)
- **Answer Relevance**: Does the response actually address the query?
- **Citation Coverage**: Are claims supported by source attribution?
- **Hallucination Rate**: What percentage of output content is unsupported or fabricated?

### Tier 3: Operational Quality

Production concerns beyond accuracy:

- **Latency**: End-to-end response time under realistic load
- **Cost**: Token consumption, embedding computation, infrastructure
- **Safety**: Refusal rates on harmful queries, policy compliance
- **Consistency**: Same question yields same answer across runs

## Key Benchmarks

| Benchmark | Scale | Focus |
|---|---|---|
| **RAGBench** | 100,000 examples | General-purpose RAG assessment |
| **CRAG** | Varies | Contextual relevance and grounding |
| **LegalBench-RAG** | Legal domain | Compliance-critical QA |
| **WixQA** | Web-scale | Factual grounding across diverse sources |
| **T²-RAGBench** | Multi-turn | Task-oriented, conversational evaluation |

## Evaluation Frameworks

- **[[entities/ragas]]**: Open-source framework with synthetic data generation, reference-free evaluation, and multiple metric implementations
- **ARES**: Adversarial testing specifically designed to stress-test retrieval systems
- **LangSmith**: LLM-as-judge evaluators with experiment tracking and detailed traces
- **TruLens**: Automated testing for retrieval precision and factual consistency
- **DeepEval**: Open-source framework for hallucination monitoring
- **AWS Bedrock**: Enterprise metrics including citation precision
- **Vertex AI**: Human and model-based evaluation in structured workflows

## Building Test Sets

A robust evaluation strategy combines three types of test data:

1. **Golden Datasets**: Frozen, manually curated question-answer pairs covering the full system scope. Essential as a stable baseline.
2. **Synthetic Datasets**: Auto-generated by tools like [[entities/ragas]] and ARES. Scale testing but require human validation to prevent learning artifacts.
3. **Human Review**: Irreplaceable for edge cases, safety-critical queries, and compliance requirements.

## Production Monitoring

Evaluation is not a one-time event. Production RAG systems require continuous monitoring:
- A/B testing of retrieval strategies and prompts
- Dashboard tracking of faithfulness and hallucination rates over time
- Drift detection when document collections change
- Governance frameworks ensuring reproducibility and auditability

## RAGAS Metric Details

[[entities/ragas]] provides reference-free metrics that use an [[concepts/llm-as-judge]] approach:

| Metric | Category | What It Measures |
|--------|----------|-----------------|
| **Context Precision** | Retrieval | Are relevant docs ranked above irrelevant ones? |
| **Context Recall** | Retrieval | What % of needed info appears in retrieved docs? |
| **Context Entities Recall** | Retrieval | Are key entities present in context? |
| **Noise Sensitivity** | Retrieval | How much does irrelevant context degrade quality? |
| **Faithfulness** | Generation | Proportion of claims supported by context |
| **Answer Relevancy** | Generation | Are all parts of the answer relevant? |
| **Factual Correctness** | Generation | Are claims factually accurate? |
| **Semantic Similarity** | Generation | Meaning preservation vs expected output |
| **Topic Adherence** | Generation | Does the response stay on topic? |

## Groundedness Monitoring in Production

[[sources/deepset-rag-groundedness]] describes deepset's Haystack approach to continuous [[concepts/faithfulness-and-groundedness]] monitoring:

- **Groundedness Score** per response, tracked over time via observability dashboards
- **Document reference analysis** showing which document positions support answers
- **Reference Predictor** providing statement-level source citations across all LLM types
- **Cost optimization**: limiting retrieved docs from 10 to 6 eliminated 40% of LLM processing costs

## Hallucination Detection for RAG

[[sources/datadog-hallucination-detection]] provides a production approach using rubric-based LLM-as-a-Judge:
- Decomposes [[concepts/hallucination-detection]] into guided summarization steps
- Classifies disagreements as contradictions, unsupported claims, or acceptable agreements
- Achieves 0.81-0.84 F1 on HaluBench/RAGTruth benchmarks
- Key insight: "LLMs are better at guided summarization than complex reasoning"

## Application to LLM Knowledge Bases

For [[concepts/llm-knowledge-base]] systems, RAG evaluation maps directly:

| RAG Component | KB Equivalent | Relevant Metric |
|---------------|---------------|-----------------|
| Retriever | Raw source selection | Context precision/recall |
| Generator | Wiki compilation | Faithfulness |
| Answer | Wiki article | Groundedness, factual correctness |
| Context | Raw sources | Completeness |

The [[concepts/linting-and-health-checks]] process is essentially continuous RAG evaluation applied to the compiled wiki.
