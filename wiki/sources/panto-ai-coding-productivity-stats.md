## Key Points

- 84% adoption, 51% daily use, 55% faster task completion in controlled experiments
- Organizational delivery metrics show inconsistent improvements despite individual gains
- AI-generated code reproduces insecure patterns and incomplete validation logic
- Recommends measuring lead time, deployment frequency, defects, security findings — not output volume
- The perception-reality gap can lead to misaligned investment decisions

## Detailed Summary

This Panto AI article provides a concise synthesis of AI coding productivity data, emphasizing the gap between task-level gains and organizational outcomes. Its key contribution is the recommendation to use DORA-style metrics (lead time, deployment frequency, change failure rate, mean time to recovery) rather than simple output metrics (lines of code, PRs merged) to assess AI tool ROI.

The security tradeoff finding aligns with [[sources/index-dev-ai-pair-programming-statistics]] data showing AI-generated APIs with weak authentication — AI tools accelerate the production of code but not necessarily the production of *secure* code.
