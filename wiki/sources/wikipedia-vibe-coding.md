## Key Points

- Karpathy coined "vibe coding" in February 2025: "fully give in to the vibes, embrace exponentials, and forget that the code even exists"
- Collins English Dictionary named it Word of the Year for 2025
- Y Combinator reported 25% of Winter 2025 startups had 95% AI-generated codebases
- Security vulnerabilities appear 2.74x more frequently in AI co-authored code (CodeRabbit, December 2025)
- GitClear analysis of 211M code changes: refactoring dropped from 25% to under 10%; duplication increased 4x
- METR study: experienced developers were 19% slower with AI tools despite perceiving 24% improvement
- Karpathy himself declared vibe coding "passe" in early 2026, proposing "agentic engineering" as the successor
- The "vibe coding hangover": senior engineers reported "development hell" managing AI-generated code

## Detailed Summary

Vibe coding represents a specific and extreme approach to AI-assisted programming where the developer describes desired functionality in natural language and accepts the LLM-generated output with minimal review. Simon Willison drew an important distinction between vibe coding and merely using LLMs as "typing assistants" -- thorough review and understanding contradicts the definition of vibe coding.

The phenomenon tracked a clear arc from excitement to disillusionment. Initial enthusiasm (February-March 2025) gave way to professional adoption (July 2025), then a documented "hangover" (September 2025) as teams confronted unmaintainable codebases. By early 2026, even its inventor had moved on to [[concepts/agentic-coding]], which emphasizes human oversight, engineering discipline, and agent orchestration rather than blind acceptance.

The security and quality data is damning: AI-generated code contains significantly more vulnerabilities, less refactoring, more duplication, and higher churn. This directly validates [[concepts/hallucination-contamination]] concerns applied to codebases rather than knowledge bases.
