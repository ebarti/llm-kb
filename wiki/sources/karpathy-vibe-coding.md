## Key Points

- Coined by [[entities/andrej-karpathy]] on February 2, 2025, in a viral X post (4.5M+ views)
- Definition: Describing projects in natural language to LLMs, accepting generated code without thorough review
- Named Collins English Dictionary Word of the Year for 2025
- Y Combinator reported 25% of Winter 2025 startups had 95% AI-generated codebases
- CodeRabbit found AI co-authored code has 1.7x more major issues than human code
- METR study: Experienced developers 19% slower with AI tools despite believing they'd be faster
- Karpathy acknowledged it suits "throwaway weekend projects" rather than production

## Detailed Summary

"Vibe coding" encapsulates Karpathy's philosophy about the changing relationship between humans and code. The term emerged from his February 2025 X post describing a style where programmers "fully give in to the vibes, embrace exponentials, and forget that the code even exists." The idea is that LLMs handle code generation while the human focuses on intent and direction.

The term's cultural impact was enormous: Collins Dictionary named it Word of the Year 2025, Merriam-Webster tracked it as trending, and it became a standard descriptor across the tech industry. However, it also attracted significant criticism. Research showed AI-generated code had more bugs, wasn't more secure, and in some studies actually slowed experienced developers. The open-source community raised concerns about reduced engagement and technical debt accumulation.

The concept connects to Karpathy's broader intellectual trajectory: [[concepts/software-2-0]] (2017) argued neural networks replace explicit code, [[concepts/post-code-ai-workflow]] (2026) described the shift from code generation to knowledge management, and vibe coding (2025) sits in between as the transitional moment when code generation itself became commoditized.
